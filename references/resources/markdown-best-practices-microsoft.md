# Markdown best practices (PowerShell docs)

## Summary

The Markdown rules Microsoft's PowerShell documentation team writes by. Not a tutorial: a concrete, enforceable style guide.

## Key takeaways

- Microsoft's docs platform uses Markdig, which follows the CommonMark spec.
- Style is enforced with the markdownlint VS Code extension (part of the Learn Authoring Pack).
- One blank line between blocks, never more; no trailing spaces; spaces, not tabs.
- ATX headings only, in sentence case, one H1 per file, and don't skip levels.
- Limit lines to 100 characters so Git diffs stay readable.
